# Telegram: выжимка сообщений чата по дням

Вы отправляете боту ссылку на чат, группу или канал. Скрипт читает **непрочитанные** сообщения
(либо последние N, либо сообщения за указанные даты) со своего пользовательского аккаунта,
делит их по суткам и присылает выжимку каждого дня.
Суммаризацию делает LLM-провайдер, выбранный в `config.toml` (Anthropic, OpenAI или любой OpenAI-совместимый).

## Установка

Нужен Python 3.11+.

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                  # и заполните
```

1. `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` — на https://my.telegram.org → API development tools.
2. `BOT_TOKEN` — создайте бота у @BotFather.
3. `ALLOWED_USER_IDS` — ваш Telegram ID. Если не знаете, оставьте любое число, запустите скрипт,
   напишите боту и возьмите ID из ответа «Нет доступа. Ваш ID: ...».
4. Ключ API выбранного провайдера (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY` или `OPENAI_COMPATIBLE_API_KEY`).
5. В `config.toml` выберите `[llm].provider` и модель.

## Запуск

```bash
python main.py
```

### Вход в аккаунт

При первом запуске скрипт входит в ваш аккаунт Telegram. По умолчанию (`[telegram].login = "qr"`)
он рисует в терминале QR-код: на телефоне откройте Telegram → Настройки → Устройства →
Подключить устройство и наведите камеру. Код живёт около 30 секунд, скрипт сам обновляет его,
пока вы не отсканируете. Если включён облачный пароль (2FA), скрипт спросит его в терминале
или возьмёт из переменной `TELEGRAM_2FA_PASSWORD` (удобно для запуска без терминала).

Вход по номеру телефона и коду из Telegram: `login = "phone"` в `config.toml`.
Дальше сессия хранится в папке `sessions/`, и повторно входить не нужно.

## Как задавать запрос боту

Отправьте боту ссылку на чат: `https://t.me/имя_чата`, `@имя_чата`, `https://t.me/c/123456789/10`
или инвайт-ссылку `https://t.me/+xxxx` (если аккаунт уже в этом чате). После ссылки можно уточнить,
что читать:

| Сообщение боту | Что будет прочитано |
|---|---|
| `https://t.me/чат` | непрочитанные сообщения |
| `https://t.me/чат 200` | последние 200 сообщений (прочитанные или нет) |
| `https://t.me/чат 10.10` | с 10 октября (с 00:00) до сегодняшнего момента |
| `https://t.me/чат 01.10 10.10` | с 1 по 10 октября, обе даты включительно |

Форматы дат: `ДД.ММ` (без года — текущий, а если такая дата ещё не наступила — прошлый),
`ДД.ММ.ГГГГ`, `ГГГГ-ММ-ДД`, а также слова `сегодня` и `вчера`. Для периода годятся и `01.10-10.10`,
и порядок «позже, раньше» (даты сами расставятся). Границы суток считаются по `timezone` из `config.toml`.
Одновременно число и даты указывать нельзя, бот ответит подсказкой.

С числом или датами сообщения читаются независимо от прочитанности, и чат не обязан быть в вашем списке
диалогов: публичные каналы можно читать без вступления. Во всех режимах действует лимит
`max_messages`; если он сработал, бот предупредит.

### Темы в группах-форумах

В группе с темами ссылка на тему читает **только эту тему**: `https://t.me/имя/2035`
(или `https://t.me/c/123456789/2035` для приватной группы), а число или даты после неё работают внутри темы:
`https://t.me/имя/2035 100`. Ссылка без номера темы читает сообщения всей группы, и бот предупредит об этом.
Номер темы — это число сразу после имени чата (ссылка на сообщение внутри темы `t.me/имя/2035/2100` тоже
читает тему 2035). Если в форуме такой темы нет (например, это номер сообщения из общей темы),
бот сообщит об этом и прочитает всю группу. В обычных группах и каналах число в ссылке — просто номер
сообщения и игнорируется. Непрочитанные считаются по самой теме.

### Меню «Мои чаты»

Каждый чат (или тема форума), который удалось открыть, **автоматически** добавляется в ваш список, и в следующий раз
его не нужно вставлять ссылкой. Список открывается постоянной кнопкой «📋 Мои чаты» под полем ввода
(она появляется после первого сохранённого чата или по `/start`) или командой `/menu`:

- нажатие на название чата присылает выжимку **непрочитанных** сообщений (как при ссылке без числа и дат);
- кнопка 🗑 рядом с названием **сразу** убирает чат из списка, без подтверждения;
- при длинном списке он разбивается на страницы по 8 чатов (кнопки ◀ ▶);
- первыми идут чаты, которыми пользовались недавно.

Что именно сохраняется: не присланная ссылка (инвайт-ссылки протухают), а публичное имя чата или его числовой id,
плюс номер темы форума и название. Число и даты из запроса не запоминаются. Если чат снова прислать, он не
дублируется, а поднимается наверх списка. У каждого пользователя из `ALLOWED_USER_IDS` свой список,
он лежит в `sessions/chats.json`. Сколько чатов хранить, задаёт `max_saved_chats` в секции `[bot]`
(по умолчанию 30): при переполнении удаляется тот, которым не пользовались дольше всего.
Личные диалоги без публичного имени в список не попадают.

### Отметка прочитанным

Если отправить боту просто ссылку (без числа и дат), то после того как вся выжимка отправлена, непрочитанные
сообщения отмечаются в Telegram прочитанными и счётчик чата (или темы) обнуляется. Отмечается всё до
последнего сообщения, попавшего в выжимку: если сработал `max_messages`, более новые остаются непрочитанными;
сообщения, пришедшие уже во время обработки, тоже. Если выжимка не удалась, ничего не отмечается.
Запросы с числом или датами ничего не отмечают. У группы-форума без указанной темы отметка не ставится
(у такой группы счётчик складывается из многих тем). Отключается: `mark_as_read = false` в секции `[telegram]`.

### Объединение малых дней

Если за какой-то день сообщений меньше `min_messages_per_day` (по умолчанию 100), он объединяется со
следующим днём, и приходит одна выжимка на несколько дней (например, «15–17 октября 2026»). Дни копятся,
пока не наберётся нужное число, так что несколько тихих дней подряд склеиваются в одну выжимку.
Последние малые дни, за которыми нет следующего, остаются отдельной выжимкой. В объединённой выжимке
у сообщений проставлены даты, модель указывает, в какой день что произошло, а лимит слов растёт
пропорционально числу дней (не больше чем втрое). `min_messages_per_day = 0` отключает объединение.

## Смена провайдера

В `config.toml`:

```toml
[llm]
provider = "openai_compatible"   # anthropic | openai | openai_compatible

[llm.openai_compatible]
base_url = "http://localhost:11434/v1"   # например, Ollama
model = "llama3.1"
```

Для локальных серверов без ключа поставьте в `.env` любое непустое значение
`OPENAI_COMPATIBLE_API_KEY`.

Провайдеры ходят в API напрямую по HTTP на стандартной библиотеке: пакеты `openai` и `anthropic`
(а с ними `pydantic-core`, который не собирается, например, в Termux) не нужны. Необязательный параметр
`timeout` (секунды, по умолчанию 180) задаётся в секции провайдера.

Чтобы добавить другой провайдер, реализуйте класс-наследник `LLMProvider` в `llm.py`
(один метод `_complete(system, user)`) и добавьте его в `build_provider`.

## Как это работает

- `auth.py` — вход по QR-коду (или по телефону).
- `store.py` — список сохранённых чатов в JSON-файле (атомарная запись, повреждённый файл не роняет
  бота, а откладывается в `.bak`). `menu.py` — кнопки списка и обработка нажатий.
- `tg_fetch.py` — разбор запроса (ссылка, число, даты). Для непрочитанных `GetPeerDialogs` даёт число и
  границу прочитанного, `iter_messages(min_id=..., reverse=True)` забирает сообщения от старых к новым;
  для периода используется `offset_date`, для «последних N» — обычный обратный обход. Тема форума
  читается через `reply_to=<номер темы>`, а её счётчик непрочитанных берётся из `GetForumTopicsByID`.
  Читаемые сообщения прочитанными сами по себе **не становятся**: отметка ставится отдельным
  шагом только после готовой выжимки и только если включён `mark_as_read`.
- `summarize.py` — группировка по суткам (в часовом поясе из конфига; малые дни объединяются),
  строки вида `[ЧЧ:ММ #номер] Автор (↩ кому ответил): текст`. Если за день слишком много текста, он режется
  на части, каждая суммаризируется отдельно, затем выжимки склеиваются.
- Промпт не привязан к теме: модель сама определяет тип чата (новости, обсуждение, вопросы-ответы,
  барахолка, болтовня) и выбирает подачу, оставляя конкретику (имена, числа, цены, даты, советы).
- `media.py` — отправка вложений, выбранных для выжимки.
- Текст переписки в промпте обёрнут в теги и помечен как данные: так модель не выполняет
  инструкции, которые кто-то написал в чате.

## Ссылки и медиа в выжимке

- **Ссылки из переписки.** В тексте для модели они заменены метками `[L1]`, `[L2]`… (рядом указан домен
  и заголовок превью). Модель ссылается на метки, а настоящие адреса подставляет код, поэтому
  выдуманных или искажённых адресов не бывает. Скрытые ссылки (слово с адресом за ним) тоже учитываются.
  Отключается: `include_links = false`.
- **Ссылки на сообщения.** У важных тем стоит `↗ https://t.me/чат/1234`. Работает для каналов и супергрупп
  (публичных и приватных — приватные ссылки открываются только участникам). У обычных малых групп и
  личных диалогов таких ссылок нет. Отключается: `include_message_links = false`.
- **Медиа.** Фото, видео и гифки размером до `max_media_mb` помечаются в переписке знаком `+`. Модель
  выбирает не больше `max_media_per_day` самых важных (по подписи, контексту и числу реакций), а скрипт
  скачивает их вашим аккаунтом и отправляет ботом под выжимкой дня (альбом уходит целиком). Картинки
  модель не разглядывает, выбор идёт по тексту вокруг. Отключается: `max_media_per_day = 0`.

## Ограничения и безопасность

- Сессия в `sessions/` даёт **полный доступ к вашему аккаунту**: не коммитьте её и `.env` в git.
  Бот отвечает только пользователям из `ALLOWED_USER_IDS`.
- Содержимое чатов отправляется выбранному LLM-провайдеру. Для приватных чатов учитывайте это
  (или используйте локальную модель через `openai_compatible`).
- Использование пользовательского аккаунта через API ограничено правилами Telegram. Не делайте частых
  запросов, лучше используйте отдельный аккаунт.
- В группах с темами (forum) без указанной темы читается вся группа, а счётчик непрочитанных —
  общий по всем темам. Для одной темы используйте ссылку `t.me/имя/номер_темы`.
- Анализируется только текст; вложения отмечаются метками `[фото]`, `[файл]` и т. п., содержимое
  картинок и видео не разбирается. Прикладываются только фото, видео и гифки (не файлы, стикеры,
  голосовые и кружки).
- Вложения из приватных чатов отправляются вам ботом, то есть проходят через серверы Telegram как обычно,
  но копии остаются в вашем диалоге с ботом.
- Если сообщений больше `max_messages`, при чтении непрочитанных и периода берутся самые старые,
  а при запросе «последние N» — самые новые.
